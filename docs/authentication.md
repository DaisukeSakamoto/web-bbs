# 認証・認可設計
## 方式
一般投稿者はユーザー名・メール・パスワード・JWT・セッションCookieを使わない。削除操作のみ投稿単位のベアラートークン（削除キー）で認可する。キー保有者が削除できるので本人の身元を証明するものではない。

## コンポーネント
- public/app.js: 削除キーをlocalStorageに保存、削除時のみJSONで送信。保存できない場合は画面に表示。共有端末ではキーが共有される。ブラウザデータ削除で紛失する。復旧機能なし。
- src/app.js: Origin一致とJSONを要求、32KBの本文上限、IPごとに60秒20回の変更リクエスト制限。CSP、nosniff、no-referrer、API no-store。Originは非ブラウザのクライアントが偽装できるため身元認証ではない。
- src/db.js: crypto.randomBytes(32) による256ビットキーを発行し、SHA-256ハッシュのみDB保存。高エントロピー乱数のためパスワード用KDFは不要。削除時はIDとハッシュをSQLのバインド変数で照合。通常の読み取りではキーもハッシュも返さない。

## リクエストフロー
1. ブラウザが POST /api/threads を送信。
2. サーバーが入力を検証、削除キーを生成、投稿とハッシュをSQLiteに保存。
3. HTTP 201で id と deleteToken を一度だけ返す。
4. ブラウザが投稿IDに関連付けてキーを保存。
5. DELETE /api/posts/:id にキーをJSONで送信。
6. サーバーがハッシュを計算しIDと一致すれば削除、204を返す。不一致は403。

## 防御と制約
SQLパラメーター化、DOM textContentでユーザー文字列を表示、外部スクリプト禁止CSP。キーはURLやログに書かない。キーに期限はなく、投稿削除で無効化される。localStorageは同一オリジンのスクリプトから読み取れるためXSS対策が重要。HTTPS必須（ローカル開発を除く）。レート制限はプロセス内・再起動で消失、プロキシ配下では全利用者が同じIPとして扱われ得る。一般投稿者に管理者権限はない。匿名とは公開画面に身元を表示しない意味で、ネットワークやホスティングのログから追跡不能になるわけではない。

GitHubへの書き込み認証はアプリの認可とは完全に独立しており、GitHubトークンをアプリに保存する必要はない。

## 管理者認証（v0.3.0）
環境変数 ADMIN_PASSWORD に強いランダムな秘密を設定する。固定長ダイジェストをタイミング安全比較し、成功時に256ビットのセッションIDを発行する。サーバーはIDのハッシュのみをメモリに1時間保持し、CookieはHttpOnly、SameSite=Strict、HTTPS時Secure、Path=/api/admin。ログアウト・再起動で失効する。管理APIは認証必須、変更系はOriginとJSON必須。5回/15分/IPのログイン制限（再起動で消失）。平文の環境変数はホスト管理者から参照可能なので保護する。単一管理者・MFAなし。公開運用前にHTTPS、秘密管理、監視を整備する。
